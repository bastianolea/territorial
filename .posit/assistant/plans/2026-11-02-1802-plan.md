# Agregar `@seealso` a las funciones de `{territorial}`

Ya tienen `@seealso` (no se tocan): `comunas()`, `regiones()`, `codigos_comunas()`, `capitales_regionales()`, `contextualizar()`, `limpiar_comunas()`.

Estilo a seguir (igual al existente): una línea `#' @seealso ...` inmediatamente antes de `#' @export`, enlaces con `[fun()]` sin prefijo `territorial::`, datasets como `[territorios]`, en español, 1–2 frases.

## Datasets (sin `@export`) — opcional

`territorios.R`, `cut_historicos.R`, `localidades.R`, `clasificacion.R` no tienen `@export`. Propongo agregarles `@seealso` antes de `@source`:
- territorios: [comunas()], [regiones()] y [codigos_comunas()] para vectores derivados de esta tabla, y [contextualizar()] para agregar sus columnas a tus datos.
- cut_historicos: [is_codigo_comuna_antiguo()] y [actualizar_codigo_comuna()] para detectar y actualizar códigos antiguos.
- localidades: [ubicar_localidades()] para encontrar la comuna de una localidad.
- clasificacion: [agregar_clasificacion()] para agregar esta clasificación a un vector de códigos comunales.

## Pasos
1. Editar cada archivo agregando la línea `@seealso` (sin tocar nada más).
2. Ejecutar `devtools::document()` para regenerar `man/` y revisar que no haya advertencias de enlaces rotos.
